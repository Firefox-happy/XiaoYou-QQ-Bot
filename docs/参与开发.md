# 参与开发

欢迎通过 issue 报告问题，或通过 pull request 提交改进。第一次参与时，选一个能独立验证的小问题最容易审查。

## 开始修改前

1. 先在 GitHub 上查看是否已有相同 issue；较大的改动可以先说明打算怎么做。
2. 在自己的分支上修改，不直接在 `main` 上开发。
3. 只提交与这次问题相关的文件。运行目录和发布仓库可能不是同一份，复制文件前先查看差异。

## 提交前检查

在仓库根目录运行：

```powershell
git status --short
git diff --check
git diff
```

确认差异中没有 API Key、密码、QQ 号、验证码、聊天记录、日志或本机绝对路径。`.gitignore` 能拦住常见运行文件，但已经被 Git 跟踪的文件不会因为后来加入忽略规则就自动停止跟踪；可用 `git ls-files` 核对。

按改动范围运行相关测试，再在 PR 描述中写清楚：触发问题的场景、改完后的行为、跑过的测试，以及仍需人工验证的部分。

## 提交与协作

```powershell
git add docs/参与开发.md
git diff --cached --check
git diff --cached
git commit -m "docs: add contribution guide"
```

提交后再决定是否推送并发起 PR。收到审查意见时，先核对触发条件和证据，再修改并补上必要验证；不必把所有建议都机械照收。
