## 掉线问题（最麻烦的一类）

### 为什么会掉线

第三方协议挂 QQ 个人号，**掉线是常态**。典型链路：

```
腾讯踢你下线 → NapCat 重启内部 Worker → 登录票据作废
   → 快速登录失败 → 密码登录 → 被要短信验证码 → 退回扫码
```

**被踢之后必须人工处理一次**，任何自动脚本都绕不过验证。
社区里的"保活脚本"（pm2 / docker restart）反而有害 —— 反复重启会让手上的验证链接失效。

### 「反检测」那行为什么重要

NapCat 有 6 个原生钩子（`hook` / `window` / `module` / `process` / `container` / `js`），
用来藏「我不是机器人」。**官方默认全开。**

检查 `catbot/napcat/napcat/config/napcat.json`：

```json
{
  "bypass": {
    "hook": true, "window": true, "module": true,
    "process": true, "container": true, "js": true
  },
  "o3HookMode": 0
}
```

**这 6 项被改成 `false` 是很坑的** —— 进程在、端口在、消息照回，
外观上完全看不出问题，只有**掉线越来越勤**这一个症状。

> 实测对照：修复前白天活跃时被踢间隔 1.3h → 0.71h → 0.95h（越来越快）；
> 修复后连续 19 小时 0 次被踢。

**另外两个配置文件名**（`napcat_<QQ号>.json`）只在 WebUI 里显示用，
**真正生效的是全局那份 `napcat.json`** —— 改错文件等于没改。

### 「稳定性」那行的判据

- **存活**：距最近一次被踢多久。一直在涨就是好消息。
- **历史中位**：过去每两次被踢之间隔多久（用中位数不用平均数 ——
  被踢间隔是重尾分布，本机样本里有过 33 小时的长间隔，平均数会被它带跑）。
- **被踢趋势**：`好转` / `持平` / `恶化`。

**面板不做「还能撑多久」的预测** —— 样本太少（十几段），任何外推都不靠谱。
看趋势比看数字有用。

### 确认没有第二个电脑端

同一账号的**第二个 PC 端**会互踢：官方 PC QQ、另一个协议端、另一台电脑。

**手机 QQ 不会和协议端冲突** —— 官方支持「一个手机 + 一个电脑」同时在线。

### 哪些操作需要重启协议层

改了 `napcat.json` 或 `bypass` 之后需要重启协议层才生效：

```bash
# 找到协议层主进程（守护进程会识别出它是谁）
tasklist | findstr node
# 杀掉主进程（守护进程会在下一轮巡检自动拉回）
taskkill /F /T /PID <主进程PID>
```

**代价**：重启后要人工登录一次（被踢后票据已作废，快速登录会失败）。
所以**登完就别再重启** —— 每重启一次换一个验证会话，手上的链接立刻作废。

## 登录相关的坑

### 配了密码回退之后，二维码不再生成

反直觉但确实如此：如果 `config/.env` 里配了密码，
且密码登录**试过了但被要验证码**，NapCat 会停在「等你完成验证」，
**不再生成二维码**。

表现：`扫码登录.bat` 弹出一张几十分钟前的**旧二维码**，扫了没反应。

**正确做法**：去 WebUI 完成验证
（状态页会打印链接，形如 `http://127.0.0.1:6099/webui/web_login?token=...`）。

**退路**：双击 `设置免扫码登录.bat` 选「清空密码」→ 重启一次，二维码就回来了。

**二维码和密码回退在这条路径下是二选一的。**

### 被踢时反而比手动重启好恢复

| 怎么起来的 | 会不会生成二维码 |
| --- | --- |
| 被踢 → NapCat 内部重启 Worker | **会**（走的是二维码兜底路径） |
| 守护进程拉起（带 `-q` 参数） | **不会**（密码回退被验证码拦住就卡住） |

所以"怎么扫码都扫不上"的第一个怀疑对象是**它是被带 `-q` 拉起来的**。

### 免扫码登录怎么工作

配置文件是 `catbot/napcat/napcat/config/.env`：

```
ACCOUNT=<机器人QQ号>
NAPCAT_QUICK_ACCOUNT=<机器人QQ号>
NAPCAT_QUICK_PASSWORD_MD5=<密码的 32 位小写 MD5>
```

MD5 算法与 NapCat 内部一致：`md5(密码的 UTF-8 字节)` 的小写 hex。

双击 `设置免扫码登录.bat` 会引导你填，**密码不会上传到任何地方**。

> **完成一次 WebUI 短信验证可能带来长期好处**：QQ 可能因此把这个设备标为可信，
> 以后快速登录就能过，不用反复要验证码。

## 语音相关

### 三级兜底

```
GPT-SoVITS（本机克隆音色）→ Edge 晓伊（免费云端）→ Windows 系统语音
```

哪一级不通就往下退，**永远不会变哑巴**。
`查看状态.bat` 的「语音能力」那行会告诉你当前用的是哪一级。

### Edge 语音不能做复杂情绪

微软的免费端点**一次只认一个 `<prosody>` 标签** —— 多个并列、
或者用 `<mstts:express-as>`，都会返回 `NoAudioReceived`。

所以真情绪要么客户端自己做起伏（`voice_emo.py`：切成 2~4 段，
每段用不同的音高语速），要么换成 GPT-SoVITS。

### GPT-SoVITS 音量偏小

它的原始输出比 Edge **轻 8~10 dB**，所以交付前过了一道响度归一化。
配置项 `voice.gptsovits_loudness`，填 `0` 关掉。

### 显存占用

GPT-SoVITS 常驻会占约 1.5 GB 显存。本项目做了**显存按需**：
空闲 180 秒就把模型从显存搬回内存，闲时只占 300 MB 左右。
搬回来约 0.35 秒，空闲后第一句话会慢 2~4 秒，第二句恢复正常。

环境变量 `GSV_IDLE_UNLOAD_SEC` 可调（`0` = 关掉这个特性）。

## 守护进程（自愈）怎么工作

`daemon.py` 每 10 秒巡检一次（链路全绿后放宽到 45 秒），负责：

1. **哪一环掉了就补回来** —— 协议层、大脑、Ollama（如果用的是本地模型）
2. **改完自动重启** —— 改动 `.py` / `config.json` 后 3~5 秒自动重启大脑
3. **卡死自动重启** —— 进程还在但不回话时，靠心跳认出来并救回来

### 「卡死」有两种，"进程还在"只答得出第一种

- 进程真的死了 → 查 pid 就知道
- **进程活着但线程池卡住** → pid 查起来一切正常，只能靠心跳文件

所以判断依据是 `catbot/run/bot.heartbeat`（每 10 秒写一次）。
心跳 90 秒没更新就判定僵死。

### 两道刹车（防止疯狂重启）

- 连续 3 次「起来就死」→ 停 5 分钟
- 每小时最多重启 6 次（活过 60 秒就松开计数）

另外 `kill_pid` **不加 `/T`** —— 否则会把 NapCat 一起带走，端口全消失。

## 冷场暖场（主动消息）

她会在两种场合主动开口：定时早安、冷场暖场。

**暖场有九道闸门**（防止变成骚扰）：

1. 静默 45 分钟以上
2. 上限 4 小时（再久就不提了）
3. 冷却 40 分钟
4. 私聊每天最多 3 次、群 1 次
5. 深夜（23:30~09:00）绝对不开口
6. 只对「她回过话的会话」暖
7. 早安后 1 小时内不暖
8. **协议层连着才发**（断线时白花推理钱还吃配额）
9. **启动后 3 分钟内不暖**（防止重启即冒泡）

> **"不要打扰"只能靠代码闸门保证**，靠提示词让它"克制一点"不可靠。

### `trigger.group_at` 是个"一头两命"的开关

关掉之后：

1. 群里 @ 她不回话（只认关键词「小柚」「猫娘」）
2. 她很少在群里回话 → 暖场状态不置位 → **群暖场一起不动**

**怀疑设置被改了**，看 `catbot/logs/bot.log` 的启动行，会打印生效配置：

```
触发方式: 群内@开/关 | 关键词[小柚, 猫娘] | 私聊开
```

## 记忆相关

- 记忆按**会话**存 —— 群聊的 key 是整个群，所以**群里别人说的话也会进上下文**；
  私聊才是一对一。
- 存在 `catbot/memory/*.json`，重启不丢。
- `memory.max_turns` 控制记几轮（默认 12，通常配 20）。
- 想清空某个会话的记忆：删掉对应的 json 文件。

> 测试时注意隔离记忆目录，否则会污染真实记忆。

## 日志在哪

| 文件 | 内容 |
| --- | --- |
| `catbot/logs/daemon.log` | 守护进程：巡检、重启、自愈 |
| `catbot/logs/bot.log` | 大脑：收消息、回话、工具调用 |
| `catbot/logs/napcat_console.log` | 协议层：登录、被踢、报错 |

日志会自动轮转（单个最大 1 MB，留 3 份）。

**日志是 GBK 编码**，用 VS Code 打开可能乱码；记事本通常正常。
